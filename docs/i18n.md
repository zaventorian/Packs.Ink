# Languages on packs.ink — localized cards and the site language layer

Started 2026-10-03. Branch `claude/i18n-languages`.

The short version: every card printed in **Japanese, German, French or Italian** is now
pulled from the publishers' own card lists, matched to our catalog, and stored in
`card_localizations` with its own art. The site can be read in those four languages
(English stays the default and the internal language), and a reader can pick the
card language separately from the site language.

---

**Coverage on the first run:** Japanese 2,500 of 2,500 Takara cards matched (2,498 by set + number + name, 2 by the
"character" rule below), plus 477 more of our rows that borrow the Japanese NAME. German 3,351 printings,
French 3,354, Italian 2,949 (Italian started at set 3; its gallery shows sets 1–2 in English).

### Which gallery cards are NOT German (or French, or Italian)

A foreign gallery lists every card, including ones that were never printed in that language (Challenge
promos, D23, most of Italian sets 1–2). Those come back with **English art and often English text**. The
language of the ART is read off the CDN key (`lorcana_de_set14_27_…`) and only cards whose art is in the
language become rows (`gallery_image_lang`).

## 2. The pipeline

```
python scripts/sync_intl_cards.py                         # dry run: fetch + match + report
python scripts/sync_intl_cards.py --commit                # + upload art, upsert rows
python scripts/sync_intl_cards.py --langs ja --commit
python scripts/sync_intl_cards.py --commit --archive "C:/Users/zaven/PacksInkBackup/card_art_intl" \
    --terms-out i18n/src/terms.json                       # + keep originals, + regenerate the glossary
python scripts/archive_zh_cards.py --archive "C:/Users/zaven/PacksInkBackup/card_art_intl"   # Chinese, local only
```

Daily in CI: `.github/workflows/intl-cards.yml` (04:40 UTC, after catalog watch). Needs the existing
`SUPABASE_URL` / `SUPABASE_SERVICE_KEY` secrets and nothing new.

| File | Job |
|---|---|
| `scripts/intl_cards.py` | the PURE half: parse each source, match to our cards, build rows, derive the glossary. No network. |
| `scripts/sync_intl_cards.py` | the network half: fetch, download art, convert, upload, upsert, prune. |
| `scripts/intl_gallery_data.mjs` | reads one gallery locale. The page embeds the catalog as a seroval `$R[n]=` JS object graph, so this **evaluates** it in a Node `vm` (null-prototype context, empty environment) instead of regexing it. |
| `scripts/test_intl_cards.py` | offline guard (runs in `guards.yml` and before every sync). |
| `scripts/archive_zh_cards.py` | local Chinese archive, never touches the DB or the bucket. |
| `supabase/179_card_localizations.sql` | the table (APPLIED 2026-10-03). |

### Matching rules — every one of them refuses rather than guesses

A wrong match puts one card's foreign art on another card's page and nothing errors, so:

* **Gallery (de/fr/it):** foreign card → its English twin by `culture_invariant_id` (the same across
  languages) → our row by **set + collector number, confirmed by name** (≥ 0.85 similarity, accents
  folded). A number hit whose name disagrees is **refused**. Fallbacks: a unique name+version inside the
  same set (renumbered promos like Challenge Promo), then a unique name+version in the whole catalog.
* **Takara (ja):** the file name embeds the English set and name (`184_DLCS3_UTC_MrSmee_BumblingMate_JA`),
  so a match needs **set + printed number AND the file slug** to agree. Takara files Into the Inklands
  under its own index (184) but prints 188 — the printed number is tried first.
  * **"character" rule:** Takara sometimes names a file after a working title the card never printed
    under (`DonaldDuck_ObliviousTraveler` is our *Donald Duck - Distracted Traveler* #212 Epic). That is
    accepted only when the **rarity agrees** and the **Japanese character name** is one a strong match
    already tied to the same English character.
* **Name-only rows (`match_how = 'name'`):** a NAME is shared by every printing (base, Enchanted, promo,
  reprint), so once any printing of a card has a Japanese name, its other printings borrow the name and
  rules text for search and display — **never the picture**.

Every non-exact match on the first run was reviewed by hand; all were right (accents, half-width glyphs,
`Vaiana`/`Moana`, two of OUR typos: Hyperia City stand-ins "Russel - Finding Adventure" and
"Merlin's Shop and Smithy - Magical Markey" — Lorcast will overwrite both).

### Art

* One **600px WebP** per foreign printing in the public `card-art` bucket at
  `intl/<lang>/<source key>.webp` (~75 KB each, ~900 MB for all four languages; Supabase is on Pro).
* Keyed on the **source's** id (Takara file name / Ravensburger `culture_invariant_id`), never our
  `card_id`, so a stand-in being retired onto Lorcast's id does not orphan its art.
* The URL carries `?v=<hash of the source version>` — `packsink-img-v1` survives deploys and keys on
  URL. A row whose stored `?v=` already matches is **not re-downloaded**, so a quiet day downloads nothing.
* **A gallery image that 404s** (seen on ~1% of German cards) retries on the app's image host
  (`gallery_api_image`). If both are gone the row is written **without** localized art (the card keeps
  its English picture) — that is not a failure; a network error is.
* `--archive DIR` keeps the full-size originals. The first run filled
  `C:\Users\zaven\PacksInkBackup\card_art_intl\{ja,de,fr,it,zh}` (~2 GB, outside OneDrive on purpose).

### Pruning is guarded

Rows for cards a source stops listing are deleted only when that language's pull came back at least 90%
of the size already on file — a partial pull from a network flake must never wipe a language.

## 3. The site language layer (Index.html)

Two independent settings, both in **⚙ Preferences → Language**:

* **Language** (`packsink:lang`) — the UI text. Synced to `user_metadata.siteLang`; a device that never
  chose adopts the account's, a choice made on this device wins (and is published).
* **Card language** (`packsink:cardLang`, default "Same as the site") — card names, rules text and art.
  A collector with English cards can read the site in Japanese and keep English art.

Both **reload the page**. Hundreds of memoized components read `_t()` at render, and a reload is the one
way to be sure none of them keeps the old language. It is also what lets the dictionary be read at module
scope.

* **Pre-paint boot** (head of Index.html): a non-English choice `document.write`s
  `<script src="/i18n/<lang>.js?v=I18N_VER">` before the app script, sets `<html lang>`. English loads
  nothing. `?hl=<lang>` previews a language for one page view without saving it.
* `_t("English string", {vars})` — dictionary lookup, falls back to the English. Keys are the English
  text, so an untranslated string is never an error. Placeholders `{name}` are filled AFTER lookup.
* `_term(kind, value)` — the publisher's own word for an ink / rarity / card type / classification / set.
* `card_localizations` is fetched once per session for the card language (IndexedDB `cardloc:<lang>`,
  24h) and applied in App: `raw = localizeCatalog(rawBase, cardLoc)` swaps `img_*` to the localized art
  (English kept as `img_*_en`) and adds `loc_name` / `loc_text` / `loc_classes`. **`"Product Name"` stays
  English** — decks, prices, legality, URLs and every comparison key on it.
  * `cardDisplayName(row)` / `cardDisplayImage(card_id, fallback)` for surfaces whose rows don't come from
    the catalog (price_movers tiles).
  * Search: `matchesCardFilter`'s haystacks include the localized name, text and classifications, so a
    Japanese query finds cards; the home quick-search ranks on either name.
* Month / weekday names: `I18N.dates` (`CAL_MONTHS`, `CAL_MONTHS_SHORT`, `CAL_DOW_SHORT`); Japanese month
  headings read `2026年10月`.
* **Nobody is prompted.** The site never switches or asks on its own (Zaven, 2026-10-03: "I dont think we
  want to prompt this to all users right off the bat"). A language is picked in ⚙ Preferences or from the
  small **language dropdown in the footer** (`.footer-lang`), on every page. A one-time "this site is in
  Japanese" banner was built and REMOVED the same day; don't bring it back without asking.
* CSS: `html[lang="ja"]` names the system Japanese faces (Hiragino / Yu Gothic / Noto Sans JP) so the
  fallback for Cinzel / Nunito Sans is a Japanese font, not a Chinese one.

### Cards a language never printed — shown anyway, with an unofficial translation

A card with no printing in the card language (a promo Japan never released, Hyperia City before its
Japanese release, Illumineer's Quest scenario cards) still shows in that setting: **its English art**,
and its rules text from an **unofficial translation** (Zaven: "can we still have it load in that setting
and just have the normal art and the card descriptions are then translated").

* `i18n/cards_mt/<lang>.json` — card_id → `{en_hash, text}`, written against each publisher's own
  keyword and reminder wording (style guides of official EN→target pairs). `en_hash` is the sha1[:12] of
  the English text it translates.
* `python scripts/load_mt_card_text.py [--commit] [--todo DIR]` writes them as `card_localizations`
  rows with `match_how='machine'`, `source='packs-ink-mt'`, **name / version / art NULL**. It runs daily
  after the sync (`intl-cards.yml`), and the run's artifact carries `mt_todo/todo_<lang>.json` — the
  cards still needing a translation (new cards, and stale ones whose English changed).
* **The official text always wins**: a card with any other row in that language is skipped; the sync's
  pruning never touches `packs-ink-mt` rows; a translation of an older English text is DELETED, not kept.
* The card modal labels it ("Unofficial translation — this card has not been printed in Japanese"),
  `.card-detail-mt-note`. Names stay English: an invented official-looking name would collide with the
  real one the day the publisher prints the card.
* On 2026-10-03 every card with rules text has text in all four languages: unofficial rows ja 618,
  it 334, de 6, fr 6 (the five oversized quest boards and one Hyperia City card).
* **Check the matcher before translating.** 58 Deep Trouble / Palace Heist cards were first sent for
  translation because `GALLERY_QUEST` still said those quests had no `sets` row; Ravensburger prints them
  in German, French and Italian. Fixed, they arrived as official rows with art. A batch of "never
  printed" cards is worth one look at the gallery for its set before it goes to translation.

### The How-it-works page

`FAQView` renders `I18N.faqHtml` when the dictionary carries one, else its English template.
`python scripts/faq_source.py` prints the English page as plain HTML (its `--hash` the English hash);
translations live in `i18n/src/faq/<lang>.html`, first line `<!-- en:<hash> -->`. `build_i18n.py` bakes
each into its dictionary and prints a note when the English has moved on (the translation keeps
rendering until redone). `test_intl_cards.py` checks every translation keeps the English page's exact
tags and attributes (it is injected as HTML), leaves `<code>`/`<kbd>` search syntax alone, carries no
script or handler, and keeps the Amazon Associates sentence verbatim.

### Dictionaries

```
i18n/src/ui.json               English string -> [ja, de, fr, it]   ("" = fall back to English)
i18n/src/terms.json            glossary per language (regenerated: sync_intl_cards.py --terms-out)
i18n/src/terms_overrides.json  hand entries the data cannot derive (Fabled = 物語のおもいで)
python scripts/build_i18n.py   -> i18n/<lang>.js   (--check: stale? untranslated keys?)
```

* Game terms follow the publishers: Japanese from Takara Tomy's own labels (攻撃力 Strength, 意志力
  Willpower, ロア値 Lore, インク可能 Inkable…), German/French/Italian from Ravensburger's gallery message
  catalog (Bernstein / Ambre / Ambra…). Classifications and set names are **derived from the card data**:
  each localized card lists its subtypes in the same order as the English card, so position-aligned pairs
  are counted and the most common translation wins (a word seen once is left out).
* **Adding a string:** wrap it — `${_t("Text")}` in a template, `title=${_t("…")}` for an attribute — add
  the key to `ui.json`, run `python scripts/build_i18n.py`, bump `I18N_VER` in the boot script.
* **Adding a language:** a source in `intl_cards.py` + `LANGS`, a column in `ui.json`, an entry in
  `SITE_LANGS` the boot's `OK` map, `DATES` in `build_i18n.py`.

### Keeping new text translated (the guards)

Added 2026-10-03, after a scan found news, the calendar page, the Screener's presets and most toasts
had shipped English-only with every guard green: the old check only knew about strings already
wrapped in `_t()`.

* **`scripts/i18n_audit.mjs`** reads Index.html's app script with a small JS lexer, walks every
  html`` template (the self-test checks it walks exactly as many as the source has) and lists
  on-screen English that is NOT routed through `_t()` / `_term()`: text nodes, visible attributes,
  string literals sitting directly in a child or visible-attribute slot, and `flashToast("...")`.
  A string passed to any call is not counted, which is what makes `_t()` the way out.
  * `node scripts/i18n_audit.mjs` - remaining untranslated strings per component (the backlog).
  * `--list [Component]` - every one, with its line.
  * `--update` - shrink the baseline after translating; it refuses to GROW it without `--accept`.
* **`i18n/src/untranslated_baseline.json`** - text -> occurrence count. `scripts/test_i18n_coverage.mjs`
  (in `guards.yml`) fails when a text appears more often than recorded (new English), or less often
  (the baseline is stale - a fixed string could quietly come back).
* **`i18n/src/english_on_purpose.json`** - what stays English and why: brands, the Amazon sentence,
  Elo / scouting pages, admin-only screens, the FAQ's English template (translated whole elsewhere).
* **`build_i18n.py --check` now FAILS** on a `_t()` key missing from ui.json (it used to print it).
  `""` in ui.json is still the deliberate "keep this English" (sentence fragments).
* **Blind spot:** text that lives in DATA (`EVENT_TILES`, `NEWS_ARTICLES`, `CALENDAR_KINDS` labels,
  Screener preset lists) never appears in a template, so the scanner cannot see it. Translate it at
  the render site with `_t(x.label)` so the key reaches ui.json, or keep per-language copies in the data.

### Other things that follow the language

* **Decklist import** (`parseDeckText`) matches localized names too (`locCardKey`: width-folded, the
  name / version separator ignored, so Takara's `ウッディ／俺が助けるぜ！` and `ウッディ - 俺が助けるぜ！`
  both land). A Japanese or German player can paste their own list.
* **Relative times** ("3日前"), **tournament placings** ("トップ8", "1位"), **month / weekday names**.
* **Canonical + hreflang**: a page rendered in Japanese declares a `?hl=ja` canonical and every page
  lists its language alternates (static copies in the head for crawlers that don't run JS).
* The footer's legal disclaimer is translated; **Amazon's required Associate sentence stays verbatim
  English** in every language.

### What is translated today

Everything a visitor sees in Index.html's templates, as of 2026-10-03 (~2,850 keys): every page, panel,
modal, tooltip, screen-reader label and pop-up message, the news tiles and the /news articles, the
calendar, the Screener, the scanner (consent notice included), the deck editor and posters, and the
data labels the pages render (calendar chips, regions, home-layout names, playmat sections, product
notes). `node scripts/i18n_audit.mjs` reports 0. What stays English is listed with a reason in
`i18n/src/english_on_purpose.json`: brands, the Amazon sentence (and the Gear note that carries it), the
Elo / scouting pages, admin-only screens, the graded-data licence terms, and search syntax.

`_tRich("…**bold**… *italic*…", vars)` keeps a sentence that bolds a button name as ONE key; use it
instead of splitting a sentence around `<strong>`.

## 4. Roadmap — what a real multi-market site still needs

Ordered by value to a Japanese player first.

1. **Collection by language.** A Japanese card is a different product with a different price. Today
   `collection_items` is keyed `(card_id, printing)` with no language, so a JP collector's owned marks are
   indistinguishable from English ones. Biggest real gap. Proposed shape (NOT built — it changes a primary
   key under every collection surface, so it wants Zaven's sign-off):
   * `alter table collection_items add column lang text not null default 'en'` and move the PK to
     `(user_id, card_id, printing, lang)`; the same for `graded_collection_items`. Every existing row is
     English by construction, so the default is the migration.
   * Client: the collection map key goes from `card_id:printing` to `card_id:printing:lang`, with `:en`
     implied when absent so every existing reader keeps working; the card tile's +/− edits the CARD
     LANGUAGE's copy (a Japanese reader adds Japanese copies), and the detail modal shows one counter row
     per language the user owns.
   * Set completion counts a card owned in any language (a Japanese master set is still a master set);
     VALUE uses the language's own price once one exists (item 2) and the English price until then, marked.
   * Exports (Dreamborn CSV) write English rows only until Dreamborn's format carries a language.
2. **Prices per market.** All prices are TCGplayer US in dollars (the settings note says so).
   * EU: Cardmarket (EUR). duels.ink already exposes Cardmarket product ids; the Cardmarket API needs an
     approved app. Cardmarket also runs an affiliate programme.
   * Japan: no TCGplayer. Candidates: Yuyu-tei, Cardrush, Hareruya 2 (shop prices, scraping terms vary),
     or eBay sold listings filtered to Japanese (the raw/graded eBay pipeline could take a language filter).
   * Currency formatting through `Intl.NumberFormat` once a non-USD price exists.
3. **Remaining UI.** Index.html is done (see "Keeping new text translated"). Still English: the
   Swiss Odds and Stream Ticker pages (standalone iframes with no dictionary of their own), privacy.html,
   the Elo pages (on purpose), and canvas exports (deck poster, card tiles) where the text is drawn rather
   than templated.
4. **SEO / sharing.** The language is client-side, so crawlers and link previews see English. Options:
   the Worker serves `?hl=ja` (or a `/ja/` prefix) with `<html lang>`, translated `<title>` / description /
   og: tags and `hreflang` alternates; the sitemap lists the alternates.
5. **Scanner.** The ORB version check matches a photo against catalog ART — adding the localized art as
   extra references would let it recognise Japanese / German prints (the name OCR is English/Chinese
   PP-OCR and does not read kana, so the art path is the one that works). Collector numbers match across
   languages.
6. **Legality by market.** Japan Core already exists as a legality filter; Japanese release dates differ
   from English (Takara's `release_date` per card is available in the sync data).
7. **Affiliates.** TCGplayer and Amazon.com are US programmes. Amazon.co.jp and Amazon.de/.fr/.it are
   separate Associates accounts; Cardmarket has its own.
8. **Chinese.** Needs a decision: the only reachable source is Dreamborn's unofficial cache (archived
   locally, not published).
9. **Discord bot / native app.** Both are English; the app store listings can be localized separately.
10. **Events.** RPH events are already worldwide; Japanese events (Takara's organised play) are not in RPH.
