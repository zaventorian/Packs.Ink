# Cards-tile magnify button + enlarged-card overlay

*Moved out of CLAUDE.md on 2026-09-30; CLAUDE.md keeps the pointer and the rules that bite.*

Every `CardTileImpl` — browse mode AND deck-builder card browser — has a tiny `.tile-magnify-btn` (22×22, inline Lucide-style SVG circle+line) in the bottom-left of the image wrap. Opens `openEnlargedCard(group)` directly, skipping the detail-modal popup. Hover-only on desktop (`opacity:0; pointer-events:none` resting → `opacity:0.9; pointer-events:auto` on `.card-tile:hover` / `:focus-within`); always-visible on touch via `@media (hover:none)`. In deck mode where the `⤢` expand button is also at `bottom:6px; left:6px`, the `.card-tile:has(.tile-expand-btn) .tile-magnify-btn{bottom:42px}` rule lifts the magnifier above it so both are tappable. **Don't re-gate the magnify on `openModal` truthy** — the initial implementation gated it that way assuming deck mode didn't pass `openModal`, but it does (the expand button needs it), so the gate was a no-op AND a stale-comment trap. Current code unconditionally wires `onMagnify` and the JSX `${onMagnify && ...}` is the always-truthy presence check.

**The select checkbox (`.card-tile-check`, top-right, Cards tab only) is ALWAYS on screen — faint (opacity 0.4) at rest, full on hover, keyboard focus or once selected** (Zaven, 2026-09-26). It used to be opacity 0 until hover, which on a touch screen made it invisible but still tappable: tapping that corner of a card selected it instead of opening it. Two consequences: the owned badge now sits permanently just below it on selectable tiles (`top:42px`; it used to jump down on every hover), and the hover rule is wrapped in `@media (hover:hover)`, because a touch screen keeps `:hover` on the last tile tapped.

**Don't re-introduce the double-click path.** Pre-fix the same intent was wired as `onDoubleClick` on the tile, with a `packsink:close-card-detail` window event the detail modal listened for to dismiss itself. Unreliable because the SINGLE-click that fires first opens the detail modal — on slow devices the modal flashes and the dblclick lands on a freshly-rendered tile underneath. The magnify-button affordance avoids the race.

**Enlarged image must scale UP**. `.enlarged-card-img` now sizes via `width: min(92vw, calc(92vh * 5 / 7), 720px); height: auto; max-height: 92vh`. The pre-fix `max-width: min(92vw, 720px)` left the image at the source's natural ~488×681 (Lorcast `image_normal`), so the "enlarged" view wasn't actually enlarged. The `calc(92vh * 5 / 7)` is the 5:7 card aspect ratio derived width — keeps the image inside the viewport on tall screens.

## A clickable tile is not a button that holds buttons — `tileOpen` (2026-10-06)

An axe scan (wcag2a/aa) flagged **nested-interactive** (serious) on every card tile on /cards (150), every movers tile on the home page (91 at 1280px) and every EV row on /analytics (14), plus **label-content-name-mismatch** on the 150 card tiles. Each was `role="button"` on the wrapper while the wrapper also held the select box, the magnifier, the camera, the TCGplayer / Amazon links or the Sim chip. A button may not contain controls: a screen reader read the whole movers tile as one 160-character name, and the inner controls were unreachable for some.

**`tileOpen(label)`** (Index.html, beside `keyActivate`) is the fix, and the pattern for any new tile of this shape:

- The wrapper keeps its `onClick` exactly as it was, **loses `role="button"`**, and goes from `tabIndex 0` to **`tabIndex -1`**. The -1 is deliberate: a mouse or finger click still focuses the tile as before, so `:focus-within` reveals, focus returning to the tile when the card modal closes, and Enter-after-a-click all behave as they did. Only Tab skips the wrapper now. Its keydown handler stays for the same reason.
- `tileOpen()` is an **empty, handler-free `<button type="button" class="tile-open" aria-label>`** as the tile's FIRST child, so Tab reaches it before the tile's own controls. Its click BUBBLES to the wrapper's onClick, so keyboard and mouse can never disagree about what opening means (in the deck builder it adds a copy, as Enter on the tile always did). Empty, so its name never turns up in find-in-page.
- `.tile-open` (styles.css, under the focus-ring block) **covers the tile** (`inset:0`) so focusing it scrolls the whole tile into view in a movers marquee, but is `clip-path:inset(50%)` + `pointer-events:none`: every click, long-press and right-click lands on the art and links under it exactly as before. The wrapper must be positioned (`.mover-tile`, `.ev-row-clickable`, `.cb-row`, `.deck-row-name` gained `position:relative`; `.card-tile`, `.gc-card`, `.gc-goal` already had it).
- The ring is drawn on the tile by `.X:has(> .tile-open:focus-visible)`. One visible difference for keyboard users only: the old global `[role="button"]:focus-visible` rule also set `border-radius:4px`, which squared a focused tile's corners; the tile now keeps its own radius under the ring.

Converted: `CardTileImpl` (browse + deck builder), `MoverTile`, `SealedMoverTile`, the EV rows, the Pins & Counters checklist row, the playmat card (was a role-less `tabIndex 0` div), the graded goal tile, the deck list row's name. The deck quick-add row only lost `role="button"` — the search box's Enter and the row's own +/− already cover it.

Measured with real catalog data (Parchment, 390px and 1280px, `/`, `/cards`, `/analytics`, `/screener`, `/decks`): nested-interactive and label-content-name-mismatch went to **0** with nothing new; colour-contrast counts unchanged. Mouse/touch behaviour diffed before vs after (click/tap on art and name, magnifier, select box, price-badge link, camera, TCGplayer link, right-click target, hit-testing at every tile's centre, marquee drag-to-pan and auto-scroll, modal swipe): identical. Element layout rects identical; the unfocused tiles screenshot pixel-identical.

**Not converted, and why:** the set-progress cards, `.cal-row-main`, `.gc-set-title-clickable`, the Screener's `.td-name-link` and the deck grid/stack `<img role="button">` hold no controls, so they are fine as role=button. The sealed and graded-tracking `.gc-card-clickable` tiles are not keyboard-reachable at all (no role, no tabIndex) — a separate gap, not this one.

Guarded by `node scripts/test_tile_open.mjs`: a scan of every `role="button"` in Index.html for nested controls, the known tiles' shape, and the CSS. **⚠ Its comment stripper is NOT test_no_emoji's one-pass regex**: that one reads the `/*` in `accept="image/*"` as a block-comment opener and swallows ~800 lines, the quick-add row among them.
